# Project comparison: drag-to-snap on macOS

All facts below are sourced from direct reads of the projects' source repositories and
their license files, except where marked "search" (from WebSearch, not independently
verified by direct fetch). See FINDINGS.md for full citations and line numbers.

| Project | Drag detection | Overlay approach | Zone model | License | Still maintained |
|---|---|---|---|---|---|
| Rectangle (rxhanson/Rectangle) | NSEvent global monitor by default; upgrades to an active CGEventTap (.cgSessionEventTap, .defaultTap) only when the user enables the Mission-Control-fighting coordinate rewrite | FootprintWindow: NSWindow, styleMask .titled (chrome hidden), isOpaque=false, level=.modalPanel, hasShadow=false, collectionBehavior .transient, animated fade + grow | Fixed 9-way directional grid (corners/edges/center) with per-edge margins and corner size; "compound" zones cycle through halves/thirds on repeated hover; separate landscape/portrait maps; fully user-remappable | MIT | Yes - active development, large user base |
| Loop (MrKai77/Loop) | Listen-only CGEventTap (.cgSessionEventTap, .listenOnly) feeding a polling comparison of live AX frame vs. frame-at-drag-start (no AXObserver used for drag detection) | ActivePanel: NSPanel, styleMask [.borderless, .nonactivatingPanel], ignoresMouseEvents=true, collectionBehavior=.canJoinAllSpaces, level = .screenSaver - 1 | Dynamic zones computed from cursor position plus screen aspect ratio (near-square vs. wide), not a static grid; inset "dead zone" in the center | GPLv3 | Yes - active development |
| Amethyst (ianyh/Amethyst) | Per-window AXObserver subscribed to kAXWindowMovedNotification/kAXWindowResizedNotification (classic observe-not-poll pattern); not a drag-to-snap tool, included as the reference AXObserver implementation | N/A - Amethyst is an always-on BSP/tiling WM, no drag preview overlay | N/A - automatic tiling layouts (BSP, columns, etc.), not a manual snap-zone model | MIT | Yes - active development |
| yabai (asmvik/yabai, formerly koekeishiya/yabai) | Active CGEventTap at kCGHIDEventTap (HID level, not session level); intercepts and swallows the mouse-down click itself when a configured modifier is held, running its own synthetic drag/resize/swap gesture entirely outside the OS's native drag | No preview overlay found in the reviewed mouse-handling code; window changes are applied directly (not verified exhaustively - flagged as a possible gap) | Target is relative to the hovered destination window, not the screen edge: center 25%-75% box (stack/swap) plus 4 triangular quadrants (BSP-split insert) | MIT | Yes - transferred to new maintainer (Asmund Vikane), active (search-corroborated) |
| AeroSpace (nikitabobko/AeroSpace) | Not a drag-to-snap tool; uses NSWorkspace app-activation notifications, not a mouse-drag detector. Deliberately avoids driving native Spaces APIs, simulating workspace switching within one persistent Space instead | N/A - keyboard-driven tiling WM, no drag preview | N/A - automatic BSP/tiling layout via keyboard commands | MIT | Yes - active development |
| MacsyZones (rohanrhu/MacsyZones) | Per-window AXObserver on kAXWindowMovedNotification, gated/throttled using CGEventSource.buttonState(.hidSystemState, button: .left) to distinguish an active drag (120Hz throttle) from any other move (0.1s throttle) | SectionWindow/LayoutWindow/GridLayoutWindow: NSWindow, borderless, isOpaque=false, ignoresMouseEvents=true (except SnapResizer), level = .statusBar +/- N, collectionBehavior [.canJoinAllSpaces, .stationary] | Fully freeform, user-authored percentage-based zones (FancyZones-style editor); optional center-hotspot (100x100pt) priority to break overlapping-zone ties | GPL-3.0 | Yes - but has an open registration-race bug (issue #89) affecting newly launched apps |

| Tiles | Unresearched - no authoritative open-source repository located | Unresearched | Unresearched | Unresearched / appears closed | Unresearched |

## Quick takeaways

- Only Rectangle and Loop are close analogues of the "drag to edge, see a preview, release to snap" interaction window-organizer wants. Amethyst and AeroSpace are automatic tiling WMs (no manual drag-to-snap), and yabai's drag interaction is modifier-gated and window-relative, not edge-relative.
- Rectangle (default NSEvent monitor, upgrade-on-demand to CGEventTap) and Loop (always-on listen-only CGEventTap, but AX-frame-polling instead of AXObserver for drag truth) are the two most directly transferable architectures, and both are permission-cheap (Accessibility only).
- Only Rectangle, Amethyst, yabai, and AeroSpace are MIT; Loop and MacsyZones are GPLv3 (approach reusable, code is not, absent a license change in window-organizer).
